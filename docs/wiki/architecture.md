# Architecture

## Runtime

- Astro 7 with `output: 'server'` on `@astrojs/cloudflare` 14 (`astro.config.mjs`). Every page is rendered per request in a Worker.
- Bindings are declared in `wrangler.jsonc`. The adapter fills in `main`, `assets`, and a `SESSION` KV binding (unused so far).
- Server code reads bindings with `import { env } from 'cloudflare:workers'` (`src/lib/db.ts`). `npm run dev` runs in workerd through the Cloudflare Vite plugin and uses the local D1 state in `.wrangler/state` (local, not versioned).
- `worker-configuration.d.ts` is generated by `npm run cf-types`. Re-run it after changing `wrangler.jsonc`.

## Data model (D1, binding `DB`)

Schema: `migrations/0001_init.sql`.

- `folders(id, parent_id, slug, name)`: a tree. The root row has `id='root'`, `parent_id NULL`, and `slug ''`. `(parent_id, slug)` is unique, so a slug only has to be unique among siblings.
- `items(id, folder_id, type, x, y, w, h, z, target_folder_id, data)`: everything placed on a canvas, in that folder's world coordinates.
  - `type` is one of `folder | image | link | embed | note | file`.
  - A folder card is an item of type `folder` whose `target_folder_id` is the folder it opens. Its position lives on the item, not on the folder.
  - `data` is JSON specific to each type. Only `folder` is rendered so far.
- Deleting a folder cascades to its subfolders, its items, and the cards that point to it.

## Routing

- `src/pages/[...path].astro` handles every URL. `loadTree()` reads all folders in one query, and `resolvePath()` walks the path slugs. An unknown path returns HTTP 404 with an in-app message.
- Each page load makes three queries: folders, the folder's items, and item counts for the folder cards.

## Canvas (`src/scripts/viewport.ts`)

- Coordinates map as `screen = world * scale + (x, y)`. The `#world` element gets one CSS transform, and the dot grid is a background on `#stage` that follows the same transform. Scale is clamped to the range 0.1–4.
- Input in view mode works like FigJam:
  - Dragging anywhere pans, including on cards.
  - Wheel or trackpad scrolling pans.
  - Ctrl/⌘ + wheel or a pinch zooms at the cursor. One mouse-wheel notch is clamped to about 1.28x.
  - A two-finger touch pinch zooms.
  - The `+`, `-`, and `0` keys zoom in, zoom out, and reset.
- Pans are never started from elements marked `[data-ui]` or `[data-interactive]`. Setting `editable = true` (phase 3) also exempts `[data-item]`, so items can be dragged.
- Folder cards are `<a href>` links. A single click is suppressed, and a double-click or double-tap (detected from pointerup timing, since iOS has no `dblclick`) navigates. Pressing Enter on the keyboard or a modified click keeps normal link behavior.
- The initial view restores the last view of that folder from `sessionStorage` (`view:<folderId>`). Otherwise it fits the content at a scale of 1 or less. `flush()` applies it synchronously to avoid a flash.

## Dev commands

- `npm run db:migrate`: apply migrations to the local D1.
- `npm run db:seed`: load sample folders from `scripts/seed-local.sql`. It wipes items and non-root folders and is for local use only.
- `npm run dev`, `npm run build`, and `npx astro check`. TypeScript is pinned to 6 because `astro check` rejects TS 7.
